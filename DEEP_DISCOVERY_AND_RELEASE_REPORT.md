## 4. Actual architecture

### Grok2API (Web Cookies)
- OpenAI-compatible gateway (`/v1/models`, `/v1/chat/completions`, SSE streaming) backed by Grok Web sessions (SSO cookie + `cf_clearance` + browser UA).
- Authentication model is Grok **Web session/cookies**, distinct from Grok/xAI OAuth (not used here).
- Admin API (`/api/admin/v1`) + Web UI (React SPA) for accounts, client keys, models, settings.
- Credentials encrypted at field level (AES-256-GCM) in SQLite; DB file is not full-file encrypted.
- HAOS add-on wraps upstream image `ghcr.io/chenyme/grok2api:v3.1.8-*`; entrypoint renders config, generates persistent secrets, bootstraps admin password and a client API key.

### FlareSolverr
- Optional internal HAOS add-on wrapping `ghcr.io/flaresolverr/flaresolverr:v3.3.25`.
- Used by Grok2API (`providerWeb.clearanceMode = flaresolverr`) to obtain `cf_clearance` + UA for Grok Web.
- LAN-only, port 8191. Does not bypass every Cloudflare challenge; specific to Grok Web clearance flow.

### HAOS
- Two separate add-ons in one repository (`repository.yaml`): `grok2api` and `flaresolverr`.
- No Home Assistant Ingress (SPA uses absolute paths); exposed on LAN port 8000 via `webui` + `watchdog`.
- Icon/logo generated by `tools/make_branding.py` (128x128 icon, 250x100 logo).
